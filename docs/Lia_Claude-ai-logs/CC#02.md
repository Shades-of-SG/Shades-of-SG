# Claude Reply (Summary):
Carousel bugs — the old logic tracked a separate index in React state and assumed all count positions (0 to N-1) were reachable scroll stops. Neither held up: manual scrolling/swiping (or animation timing) desynced the stored index from the real scroll position, causing the "needs multiple clicks" symptom, and on wider screens showing multiple cards at once, only count - visibleCards positions are actually reachable — so the modulo math targeted positions the browser would just clamp away, which is why "forward" on the last card looked stuck instead of looping. Rewrote Carousel.jsx to work directly off real scroll boundaries: it checks the track's actual scrollLeft/scrollWidth — if already at the end, forward wraps to scrollLeft: 0; if at the start, back wraps to the end; otherwise it steps by exactly one card's width. Verified this cycles correctly in both directions at both single-card (phone) and multi-card (laptop) widths.

Responsive overflow — .page-stack and .content-section were CSS grids without an explicit grid-template-columns, so their implicit single column could grow to fit its widest child's content instead of shrinking to the viewport — a latent bug exposed once the new sections (rhythm stats, badge shelf, stat cards) added wider content. Fixed by constraining those (and .page-header, .section-card/.song-card/.state-box, .rhythm-stat-card) to grid-template-columns: minmax(0, 1fr). Confirmed zero horizontal overflow at 960px/680px (split-screen) and 375px (phone) for both the guest landing page and the logged-in homepage, with no console errors.
