# Claude Plan
Song Library — Report Song Feature
Context
Song Library currently lets logged-in users bookmark songs from the catalogue row, but there is no way for anyone to flag a song that is inappropriate, mislabeled, spam, or otherwise problematic. The request is to add a Report action to each song catalogue row — placed after Bookmark, before Open — so users can report a song, plus (per follow-up decision) a basic admin queue so reports don't just disappear into the database unseen.

There is currently no report/flag system anywhere in the app for user-submitted content. The closest existing patterns, which this feature will copy rather than reinvent:

Bookmarks (song_bookmarks table, SongBookmark model, PUT /songs/:id/bookmark) — for the request/response/optimistic-UI shape of a per-user-per-song action tied to the catalogue row.
Safety Reports admin workspace (ReportWorkspace in frontend/src/pages/AdminCommunityPage.jsx, GET/POST /admin/safety-reports*) — for the shape of an admin review queue with reasons, resolution outcomes, and audit logging via ModerationAction.
Decisions confirmed with the user:

Report button is hidden for guests (exactly like the Bookmark button — isAuthenticated gate).
Include a basic admin queue ("Song Reports") mirroring the existing Safety Reports tab.
"Already reported" state is session-only (no extra join needed on GET /songs); the backend still rejects a second pending report for the same song/user with a friendly "already reported" response, so refreshing and re-submitting is harmless.
No existing data is ever deleted or altered — this feature only adds a new table via a new migration file and new, additive code paths. Nothing in song_bookmarks, moderation_actions, or any other existing table/route/component is modified.
1. Database (additive only)
New migration backend/migrations/025_song_reports.sql (next free number after 024_*):

create table if not exists song_reports (
    id uuid primary key default gen_random_uuid(),
    user_id uuid not null references users(id) on delete cascade,
    song_id uuid not null references songs(id) on delete cascade,
    reason varchar(32) not null
        check (reason in ('INAPPROPRIATE', 'COPYRIGHT', 'SPAM', 'METADATA', 'OTHER')),
    details text,
    status varchar(32) not null default 'PENDING'
        check (status in ('PENDING', 'REVIEWED', 'DISMISSED')),
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);

create index if not exists song_reports_song_idx on song_reports (song_id, created_at desc);
create index if not exists song_reports_user_idx on song_reports (user_id, created_at desc);
create index if not exists song_reports_status_idx on song_reports (status, created_at desc);
Duplicate-pending prevention is enforced at the application layer in the controller (check-then-create), not a DB constraint — keeps SQLite (used in dev/test) and Postgres behavior identical, and matches how other duplicate checks in this codebase are already done (e.g. findOrCreate in toggleBookmark).

2. Backend API

backend/controllers/songController.js — add reportSong, following toggleBookmark's exact error-handling shape (song existence + PUBLISHED check, requireAuth-populated user, next(error) on failure):

const REPORT_REASONS = new Set(['INAPPROPRIATE', 'COPYRIGHT', 'SPAM', 'METADATA', 'OTHER']);

async function reportSong(req, res, next) {
    try {
        const song = await Song.findOne({ where: { id: req.params.id, status: 'PUBLISHED' } });
        if (!song) return res.status(404).json({ message: 'Song not found.' });

        const reason = String(req.body.reason || '').toUpperCase();
        if (!REPORT_REASONS.has(reason)) {
            return res.status(400).json({ message: 'Please choose a valid report reason.' });
        }
        const details = req.body.details ? String(req.body.details).trim().slice(0, 1000) : null;
        const userId = req.authUserRecord.id;

        const existingPending = await SongReport.findOne({ where: { userId, songId: song.id, status: 'PENDING' } });
        if (existingPending) {
            return res.status(409).json({ message: 'You already have a pending report for this song.', code: 'ALREADY_REPORTED' });
        }

        const report = await SongReport.create({ userId, songId: song.id, reason, details });
        return res.status(201).json({ report: { id: report.id, reason, status: report.status } });
    } catch (error) {
        return next(error);
    }
}
