Landing page + Song Library overhaul
Context
The Landing page lost its carousel behavior during a prior integration (the Carousel component and its CSS still exist, fully working, but Landing.jsx renders plain grids instead) and its community stats call fails for guests because the /api/stats route is wrongly locked behind requireAdmin. Separately, the Song Library's search/filter/sort tooling is a first pass (single-select native <select>s, search matches too many fields, no highlighting, no bookmarking) that needs to become richer: multi-select filters, per-value active-filter chips, a locale-aware sort with direction toggle, search-term highlighting scoped to name/creator, and a new per-user bookmark feature that pins matches to the top of the list. All changes stay scoped to the Landing page and Song Library page/components — no other pages touched, and no destructive DB changes (only an additive migration for a new join table).

1. Landing page
Carousel restore — frontend/src/pages/Landing.jsx

Carousel (frontend/src/components/Carousel.jsx) is already imported but unused, and already implements exactly the required behavior: caps at 5 items, scrolls by measured item width (getStep()) so items snap fully into view (CSS scroll-snap-type: x mandatory / scroll-snap-align: start at frontend/src/App.css:11716-11791), and loops start↔end on button press. No changes needed to Carousel.jsx or its CSS.

Keep songs.slice(0,5) / reflections.slice(0,5) as-is (belt-and-suspenders with the carousel's own internal 5-item cap).
Stats 401 fix — backend/routes/stats.js:7

Root cause confirmed: GET /api/stats is wrapped in requireAdmin, but it's called unauthenticated from Landing for every visitor (frontend/src/services/statsService.js:3-8). requireAdmin → requireRoles('ADMIN') → backend/middleware/auth.js:53-55 returns 401 "Please log in to continue." for anyone without a token.
Fix: drop the auth middleware entirely on router.get("/", ...) (this matches the existing public-read pattern used by GET /api/songs and GET /api/folders, which also take no auth middleware). getStats() doesn't use req.authUser at all, so no other change is needed. Leave GET /api/stats/me (requireAuth) untouched.
2. Song Library — backend (backend/controllers/songController.js, backend/routes/songs.js)

Parse each into an array; where.theme becomes { [Op.in]: themes } when 1+ values given; language/mood in-memory checks change from single-value .includes to "song's languages/moodTags array intersects the requested set".

Bookmarks (per-user, new join table) — following the existing Folder/SongFolder pattern exactly:

New model backend/models/SongBookmark.js: userId (UUID, PK part), songId (UUID, PK part), composite PK, underscored: true, tableName: 'song_bookmarks'.
New migration backend/migrations/021_song_bookmarks.sql:
create table if not exists song_bookmarks (
    user_id uuid not null references users(id) on delete cascade,
    song_id uuid not null references songs(id) on delete cascade,
    created_at timestamptz not null default now(),
    primary key (user_id, song_id)
);
create index if not exists song_bookmarks_song_idx on song_bookmarks (song_id);
(The existing unused bookmark boolean column on Song — never migrated — is left alone; not deleted, just superseded/unused, per "never erase from the database".)
Register associations in backend/models/index.js: User.hasMany(SongBookmark, ...), SongBookmark.belongsTo(Song, ...), and export SongBookmark.

Any DB failure falls through to next(error) → non-2xx response, which the frontend uses as the signal to revert its optimistic UI change.
Import requireAuth (already exported from middleware/auth.js) into songs.js alongside the existing requireCreator import, and add the new route.
